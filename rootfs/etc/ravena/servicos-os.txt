# RAVENA OS -- OS-2: mapa pacote -> unit systemd
#
# O que e: para CADA pacote do OS-1 e para CADA unit ravena-* que ja existe no
# repo, diz qual unit systemd correspondente e se ela ja existe aqui ou so
# aparece depois da instalacao. Serve para nao inventar unidade duplicada e para
# o build saber o que habilitar.
#
# FORMATO -- 4 campos, separados por " | ", sem espaco antes/depois:
#   pacote | unit | estado | origem
#
# pacote: nome exato como em pacotes-os.txt, ou "ravena" (unidades proprias)
# unit  : nome da unit SEM caminho. "ravena-*" = nossa. Outros = upstream.
# estado (enumerado, o teste valida):
#   existe_repo = o arquivo da unit JA esta em rootfs/etc/systemd/system/
#   pendente    = a unit so aparece depois que o pacote for instalado
#   nao_aplica  = o pacote e CLI/library puro, nao sobe daemon
# origem: doc1#<n> | doc2#<n> | plano-OS-1 | plano-OS-2 | upstream
#
# SYMLINKS (modo 120000) -- no Windows o Git materializa isto como arquivo de
# texto; o conteudo e checado pelo indice (`git ls-files -s`), nao por find.
# Hoje ha exatamente 6, todos para units do systemd-networkd (upstream):
#   systemd-networkd.service / .socket / -wait-online.service /
#   -varlink.socket / -varlink-metrics.socket / -resolve-hook.socket
# Nenhuma unit ravena-* esta habilitada por symlink no repo -- habilitacao
# acontece no preparo do rootfs, fora do git.
